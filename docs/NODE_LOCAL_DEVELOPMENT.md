# Graphite — автономный локальный Node.js (только разработка)

Этот режим — **локальный прототип**, а не схема выпуска на Beget.
Реальный Graphite Site, его D1, MCP-плагин и существующие сюжеты не
используются. Он работает с собственным файлом SQLite и настоящими
REST/MCP-контрактами исходного Worker через закрытый локальный шлюз.

## Запуск (Windows PowerShell, Node.js 22+)

```powershell
cd D:\Graphite\plot-architect
git pull
cd site
npm ci
npm run test:node-local
npm run dev:node-local
```

В окне появятся:
- URL редактора `http://127.0.0.1:8788/`;
- путь отдельной базы данных `%USERPROFILE%\.graphite-local\graphite-dev.sqlite`;
- **временный локальный ключ** для формы входа и тестового MCP Bearer.

Открой страницу в браузере и введи временный ключ из терминала.
Сам ключ **никому не пересылай и не снимай на скриншот**.
После перезапуска сервера ключ сменится; SQLite-данные останутся.
Остановить — Ctrl+C. При занятом порте можно до запуска задать
`$env:GRAPHITE_LOCAL_PORT = '8789'`. Сервер всегда слушает только
`127.0.0.1`, и Host обязан совпадать с этим локальным адресом.

Для запуска npm build, Wrangler, Docker, регистрации плагина или ключа
OpenAI Platform **не требуется**. Не переиспользуй для этого режима
данные из `.wrangler/state` и не копируй сюда рабочие сюжеты.

## Что реализовано и что проверяют тесты

- Один файл SQLite: созданные через MCP проекты доступны через REST и
  редактор; REST-изменения читаются через MCP.
- Текущие инварианты: ревизии, CAS, защищённое применение предложений,
  изоляция черновиков и атомарные операции `batch()`.
- Browser UI: временный ключ → HTTP-only SameSite=Strict cookie.
- MCP: только `Authorization: Bearer <локальный ключ>`. Cookie для
  MCP **недостаточно**, даже если браузер вошёл.
- Любая браузерная операция записи требует точный `Origin`.
  Присланный клиентом `oai-authenticated-user-id` удаляется; шлюз
  выставляет служебный идентификатор **после** своей проверки.
- Неизвестная или неполная существующая SQLite-схема блокирует запуск,
  а не мигрируется автоматически.
- По умолчанию творческий workflow REST отключён, как и в исходной
  реализации. Тесты не переводят реальные черновики в канон.

`npm run test:node-local` проверяет HTTP, UI, MCP и сохранение через
перезапуск SQLite; `npm run test:sqlite` — атомарность и контракты
хранилища. Все тесты используют **временные синтетические БД**.

## Ограничения безопасности и следующее решение

**Не публиковать этот порт, не настраивать публичный прокси,
не подключать Secure MCP Tunnel к этому HTTP-серверу и не разворачивать
его на VPS.** Локальный HTTP не использует TLS или OAuth 2.1. Cookie
предназначена только для браузера на той же машине; ключ меняется
при запуске и не является полноценной системой учётных записей.
Локальные процессы могут иметь доступ к пользовательским файлам.

Для Beget нужен отдельный PR: проверенная браузерная авторизация и
сессии, OAuth MCP с discovery/PKCE/audience, TLS/reverse proxy, защита
секретов, надёжное резервное копирование SQLite и проверенное
восстановление. После этого — изолированный staging с отдельным
разрешением владельца.

Принятые архитектурные рамки: Library
`/Планировщик сюжета/Development/GRAPHITE_BEGET_MCP_PLAN.md`.
История реализации — только GitHub PR/CI. Никакого Site Deploy,
миграции D1 или пользовательских сюжетов в данном этапе нет.
