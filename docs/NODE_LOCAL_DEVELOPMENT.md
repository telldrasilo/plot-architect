# Graphite — автономный локальный Node.js (только разработка)

Этот режим — **локальный прототип**, а не схема выпуска на Beget.
Реальный Graphite Site, его D1, MCP-плагин и существующие сюжеты не
используются. Он работает с собственным файлом SQLite и настоящими
REST/MCP-контрактами исходного Worker через закрытый локальный шлюз.

## Запуск (Windows PowerShell, Node.js 22+)

```powershell
cd D:\Graphite\plot-architect
git pull
cd site
npm ci
npm run test:node-local
npm run dev:node-local
```

В окне появятся:
- URL редактора `http://127.0.0.1:8788/`;
- путь отдельной базы данных `%USERPROFILE%\.graphite-local\graphite-dev.sqlite`;
- **временный локальный ключ** для формы входа и тестового MCP Bearer.

Открой страницу в браузере и введи временный ключ из терминала.
Сам ключ **никому не пересылай и не снимай на скриншот**.
После перезапуска сервера ключ сменится; SQLite-данные останутся.
Остановить — Ctrl+C. При занятом порте можно до запуска задать
`$env:GRAPHITE_LOCAL_PORT = '8789'`. Сервер всегда слушает только
`127.0.0.1`, и Host обязан совпадать с этим локальным адресом.

Для запуска npm build, Wrangler, Docker, регистрации плагина или ключа
OpenAI Platform **не требуется**. Не переиспользуй для этого режима
данные из `.wrangler/state` и не копируй сюда рабочие сюжеты.

## Что реализовано и что проверяют тесты

- Один файл SQLite: созданные через MCP проекты доступны через REST и
  редактор; REST-изменения читаются через MCP.
- Текущие инварианты: ревизии, CAS, защищённое применение предложений,
  изоляция черновиков и атомарные операции `batch()`.
- Browser UI: временный ключ → HTTP-only SameSite=Strict cookie.
- MCP: только `Authorization: Bearer <локальный ключ>`. Cookie для
  MCP **недостаточно**, даже если браузер вошёл.
- Любая браузерная операция записи требует точный `Origin`.
  Присланный клиентом `oai-authenticated-user-id` удаляется; шлюз
  выставляет служебный идентификатор **после** своей проверки.
- Неизвестная или неполная существующая SQLite-схема блокирует запуск,
  а не мигрируется автоматически.
- В штатном локальном запуске творческий workflow **включён** для
  авторизованного владельца: `preview_note_drafts` → `save_note_drafts`
  сохраняет отдельную рабочую область с черновыми нодами и внутренними
  связями без принятия в канон. Перед сохранением обязателен review_token
  и проверка ревизии. Hosted Worker по-прежнему отключает workflow по
  умолчанию; созданный напрямую без флага локальный сервер тоже.

`npm run test:note-local` проверяет полный цикл: создать синтетическую
заметку → получить задачу → preview без записи → сохранить отдельные
черновики с рабочей областью → повторить idempotent-запись → проверить
неизменность канонического графа и действующий режим default-off.

`npm run test:node-local` проверяет HTTP, UI, MCP и сохранение через
перезапуск SQLite; `npm run test:sqlite` — атомарность и контракты
хранилища. Все тесты используют **временные синтетические БД**.

## ChatGPT через отдельный Secure MCP Tunnel (личный ПК)

После локальных тестов используем **отдельный** туннель и отдельный
приватный плагин «Graphite Local». Не изменяй существующие Graphite
Site/плагин, их D1, или синтетический «Graphite MCP Probe».

1. В [OpenAI Platform Tunnels](https://platform.openai.com/settings/organization/tunnels)
   создай **новый** приватный туннель. Сохрани его ID \`tunnel_...\`.
   Не используй ID тестового Probe.
2. Останови обычный \`npm.cmd run dev:node-local\` через Ctrl+C —
   только один сервер может слушать порт 8788.
3. В **новом** PowerShell установи путь клиента, ID и runtime API key
   (ключ с правами **Tunnels Read + Use**). Сам секрет никуда не
   записывай и не вставляй в чат. Для ввода используется скрытая строка.

\`\`\`powershell
cd D:\Graphite\plot-architect
git pull --ff-only
$env:GRAPHITE_TUNNEL_CLIENT_EXE = (Get-ChildItem "D:\Graphite\tunnel-client" -Recurse -Filter tunnel-client.exe | Select-Object -First 1).FullName
$env:GRAPHITE_TUNNEL_ID = "tunnel_ВСТАВЬ_ID_НОВОГО_ТУННЕЛЯ"
$secureKey = Read-Host "OpenAI Platform runtime key" -AsSecureString
$env:CONTROL_PLANE_API_KEY = [System.Net.NetworkCredential]::new("", $secureKey).Password
Remove-Variable secureKey
cd site
npm.cmd run test:mcp-bridge
npm.cmd run dev:node-tunnel
\`\`\`

Это **одна команда запуска** для локального Graphite и официального
\`tunnel-client\`. Она передаёт случайный временный локальный Bearer-ключ
своему дочернему MCP-процессу через окружение, **не в argv, YAML, GitHub
или Plugin-конфигурацию**. Туннель запускает только узкий stdio-адаптер
\`mcp-local-stdio.mjs\`; он переадресует MCP-запросы на закрытый
\`http://127.0.0.1:8788/mcp\`. Внешний HTTP не открыт.

Адрес редактора останется \`http://127.0.0.1:8788/\`. Для входа в
браузере используется **временный локальный ключ** из терминала.
Перезапуск сменит ключ, но сохранит SQLite-сюжеты. Текущий туннель
работает только пока оба процесса запущены.

4. В ChatGPT → Plugins → Add custom MCP server создай **новый
   приватный** «Graphite Local»: Connection **Tunnel**, выбери **новый**
   ID. Для ChatGPT-коннектора используется «No authentication»,
   поскольку этот туннель настроен как приватный, а шлюз требует
   внутренний временный Bearer. Не публикуй коннектор и не предоставляй
   доступ другим пользователям без отдельной модели авторизации.
5. Проверь \`list_projects\`, затем \`create_project\` **только по
   явному согласию владельца** с тестовым названием. Проверь, что
   проект появился в браузере, и можно прочитать его через
   \`get_project\`. Не используй реальные сюжеты в первом smoke-test.

Если ошибка \`tunnel-client\`: сначала убедись, что \`GRAPHITE_TUNNEL_ID\`
указывает **на новый** туннель и runtime key верен. Не присылай
API-ключ или локальный ключ в чат. Можно прислать только сообщения
\`doctor\`/\`run\` без секретов.

В этой схеме нет вызовов **OpenAI model API**, но runtime-ключ
используется для работы туннеля; запросы к MCP идут через OpenAI.
Сюжеты остаются в SQLite на твоём ПК, однако данные, выбранные для
передачи по MCP, проходят через инфраструктуру OpenAI. Работа
возможна только пока ПК включён и сервер с туннелем запущены.

## Ограничения безопасности и следующее решение

**Не публиковать этот порт, не настраивать публичный прокси,
не подключать Secure MCP Tunnel к открытому HTTP-серверу напрямую и
не разворачивать его на VPS.** Для личного ChatGPT допускается
только описанный выше приватный stdio-мост с внутренним Bearer-ключом. Локальный HTTP не использует TLS или OAuth 2.1. Cookie
предназначена только для браузера на той же машине; ключ меняется
при запуске и не является полноценной системой учётных записей.
Локальные процессы могут иметь доступ к пользовательским файлам.

Для Beget нужен отдельный PR: проверенная браузерная авторизация и
сессии, OAuth MCP с discovery/PKCE/audience, TLS/reverse proxy, защита
секретов, надёжное резервное копирование SQLite и проверенное
восстановление. После этого — изолированный staging с отдельным
разрешением владельца.

Принятые архитектурные рамки: Library
`/Планировщик сюжета/Development/GRAPHITE_BEGET_MCP_PLAN.md`.
История реализации — только GitHub PR/CI. Никакого Site Deploy,
миграции D1 или пользовательских сюжетов в данном этапе нет.
